# QuantumBridge-Tox v0.7 — matched DFT versus matched non-DFT control

This is an **additive development-only extension** of v0.6. It does not modify previous versions, checkpoints, input datasets, the 1,219-molecule frozen test set, or existing result directories. It is intended for CPU use.

## Inputs expected in the existing project folder

- `gnn_quantumbridge.py` (v0.3, unchanged)
- `gnn_quantumbridge_v05.py` (v0.5, unchanged)
- `data/qm9.csv`, `data/tox21_clean.csv.gz`
- `data/qmugs/qmugs_v06_pool.csv.gz` — the already extracted 32,023-molecule pool
- `results/gnn_v03_5k/tox_split.csv` — the **frozen** v0.3 split
- The current Python `.venv` with NumPy, pandas, RDKit, SciPy, scikit-learn, and CPU PyTorch

You do **not** need to re-download the original 2 GB QMugs `summary.csv` or to rerun the extractor.

## New scientific control

v0.6 compares matched QMugs DFT pretraining with **random-sample** QMugs RDKit pretraining. v0.7 adds `qmugs_matched_rdkit` to isolate the target type more cleanly:

| Variant | Pretraining molecules | Supervision |
|---|---|---|
| `qmugs_matched` | Domain-matched QMugs | QMugs DFT μ, HOMO, LUMO |
| `qmugs_matched_rdkit` **NEW** | **Exactly the same matched InChIKeys** | RDKit MolWt, TPSA, LogP, HBD |
| `qmugs_random` | Random QMugs | DFT μ, HOMO, LUMO |
| `qmugs_rdkit` | **Exactly the same random InChIKeys** | RDKit properties |
| `qm9_dft` | QM9 | DFT μ, HOMO, LUMO |
| `scratch` | No pretraining | Tox21 labels |
| `random_forest` | No neural-network pretraining | Tox21 labels |

A new `selection_sha256` field and `pretraining_selection.csv` record molecular identity selection. An internal assertion checks matched DFT and matched RDKit share their training identities. QMugs DFT and RDKit controls also use the same fixed pretraining validation molecules.

This **still does not prove a causal DFT effect**: label type, target difficulty, and learned optimization trajectories differ. It is a much cleaner control than v0.6, not a fully randomized causal intervention.

## Short CPU smoke test

```bash

set -o pipefail
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v07.py \
  --seeds 42 --n-pretrain 500 --qm9-val-n 100 --qmugs-val-n 100 \

  --hidden 32 --batch 32 --threads 2 \
  --out results/gnn_v07_smoke \

```

**Never point `--out` at a previous result directory**; existing nonempty output directories are intentionally refused.

## Outputs

- `summary.csv`: mean and standard deviation of ROC-AUC, PR-AUC, F1 and MCC.
- `development_results.csv`: per-seed values with inner-validation-selected thresholds.
- `paired_controls.csv`: **within-seed** contrasts for matched DFT vs matched RDKit, random DFT vs random RDKit, matched DFT vs random DFT, matched RDKit vs random RDKit, and relevant baselines.
- `paired_controls_summary.csv`: aggregate paired contrasts across seeds.
- `selection_audit.csv`: distributions of selected pretraining molecules and SHA256 set hashes.
- `pretraining_selection.csv`: exact QMugs training InChIKeys chosen for each seed.
- `pretraining_metrics.csv`: DFT and RDKit property MAE, RMSE and R² **on their respective validation distributions**.
- `dev_predictions_seed<seed>.csv`, `dev_split_seed<seed>.csv`, `manifest.json`.

## Interpretation and safeguards

- Results are **development-only**, not independent final test performance. The prior v0.3 test identities must remain untouched until a separately defined final protocol.
- The three development seed splits overlap. Three positive deltas do not establish significance.
- F1/MCC are threshold-dependent. Cutoffs are chosen on inner validation, not outer development evaluation.
- DFT regression R² is calculated on molecular QMugs or QM9 validation sets. Do not directly compare R² across different datasets as if their target distributions were identical.
- Only 2D graphs are used; the quantum labels depend in part on 3D conformer geometry. Only one `conf_00` structure per ChEMBL record was retained in the QMugs pool, not necessarily the lowest-energy conformer.
- The matching criterion uses only inner-training molecular descriptors and can over-select some chemistry while underrepresenting halogenated compounds. Use a larger/fixed external evaluation to support deployment claims.
- The new paired control compares different **pretraining target sets** on the same molecules. It does not by itself show that DFT quantum knowledge is uniquely responsible for any performance gain.

The code was checked for syntax, exercised by a deterministic selection/paired-comparisons test, and run end-to-end on a **small synthetic** project fixture. No real v0.7 Tox21/QMugs performance has been computed here.
