# QuantumBridge-Tox v0.6 — QM9 versus QMugs (development-only)

This extension is **additive**. It expects the user's existing, unmodified files:

- `gnn_quantumbridge.py` (original v0.3)
- `gnn_quantumbridge_v05.py` (v0.5)
- `data/qm9.csv`
- `data/tox21_clean.csv.gz`
- `data/qmugs/summary.csv` (user-downloaded ~2.03 GB file)
- `results/gnn_v03_5k/tox_split.csv` (frozen original test assignments)

New files in this package:

- `extract_qmugs_v06.py`: stream QMugs data into a small, validated chemical pool.
- `gnn_quantumbridge_v06.py`: compare pretraining data sources under a common model, 3 DFT labels, and shared toxicity development splits.
- `README_v06.md`: instructions.

## Step 1 — extract a bounded-memory QMugs pool

```bash
cd ~/Downloads/QuantumBridge-Tox
source .venv/bin/activate
python extract_qmugs_v06.py \
  --source data/qmugs/summary.csv \
  --tox data/tox21_clean.csv.gz \
  --sample-rate 0.05 \
  --chunksize 20000 \
  --out data/qmugs/qmugs_v06_pool.csv.gz \
  --audit-out data/qmugs/qmugs_v06_audit.json
```

**Important:** This scans the full 2 GB CSV in chunks and can take several minutes on CPU; it never loads the whole file into RAM. For reproducibility, `chembl_id` is selected by a fixed stable cryptographic hash. Only `conf_00` is retained per molecule, so this is **not** a conformer ensemble, and `conf_00` is **not necessarily the lowest-energy conformer**. Missing/non-finite DFT labels, flagged negative-frequency records, salts/multifragment structures, duplicate molecular InChIKeys, and ALL Tox21 InChIKeys are excluded. Inspect the audit before training. If you need a different sample rate, specify NEW `--out` and `--audit-out` paths; outputs will never be overwritten.

Extracted fields are named `mu`, `homo`, and `lumo`, derived respectively from **DFT_DIPOLE_TOT**, **DFT_HOMO_ENERGY**, and **DFT_LUMO_ENERGY**. `GFN2_POLARIZABILITY_MOLECULAR` is not DFT and is not used. QMugs has multiple conformer rows, which must never be treated as independent molecular identities in training/evaluation.

Inspect extraction:

```bash
python - <<'PY'
import pandas as pd, json
p='data/qmugs/qmugs_v06_pool.csv.gz'
d=pd.read_csv(p)
print('Unique QMugs molecules:',len(d),'duplicate keys:',d.inchikey.duplicated().sum())
print('Medians:',d[['heavy_atoms','mw','logp','aromatic_rings']].median().to_dict())
print('Targets:',d[['mu','homo','lumo']].isna().sum().to_dict())
print(json.dumps(json.load(open('data/qmugs/qmugs_v06_audit.json'))['counts'],indent=2))
PY
```

## Step 2 — one-seed CPU smoke test

```bash
mkdir -p logs
set -o pipefail
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v06.py \
 --seeds 42 --n-pretrain 500 --qm9-val-n 100 --qmugs-val-n 100 \
 --pretrain-epochs 2 --finetune-epochs 2 --patience 2 \
 --hidden 32 --batch 32 --threads 2 \
 --out results/gnn_v06_smoke \
 2>&1 | tee logs/gnn_v06_smoke.log
```

The output contains `summary.csv`, `pretraining_metrics.csv` (MAE / RMSE / R²), `paired_deltas.csv` (relative to scratch), `selection_audit.csv`, and per-seed development predictions. It reports ROC-AUC, PR-AUC, F1, MCC. Note all numbers are development estimates. The original v0.3 test molecules are excluded from v0.6 model fitting, tuning and evaluation.

## Variants

- `random_forest`: fingerprint control, no pretraining.
- `scratch`: same 2D GNN, no pretraining.
- `qm9_dft`: QM9 DFT targets μ / HOMO / LUMO.
- `qmugs_random`: random QMugs DFT μ / HOMO / LUMO pretraining.
- `qmugs_matched`: QMugs DFT pretraining on compounds closest to the **inner-training** Tox21 chemistry in robust-scaled heavy-atom count, molecular weight, logP and aromatic ring count. No toxicity labels or outer-evaluation/test data enter matching.
- `qmugs_rdkit`: non-DFT pretraining control with RDKit properties on the **same random QMugs molecules**.

All GNN variants use the same architecture and inner-development split for each seed. Each source has its own fixed pretraining validation subset. Since QM9 B3LYP and QMugs ωB97X-D/def2-SVP DFT calculations differ, source comparisons **confound chemical coverage and quantum method**. Different pretraining validation distributions likewise make direct comparison of cross-source MAE/R² inappropriate. Also note this is a 2D GNN; it has no 3D conformer geometry, despite geometry-dependent DFT targets. Any conclusion about efficacy or causes remains exploratory.

## Troubleshooting

If extraction says the pool has fewer than 6,000 molecules, rerun with `--sample-rate 0.10` but with **new** output names, then pass that new pool to the training program using `--qmugs-pool ...`.

If an interrupted attempt leaves a nonempty results directory, choose another `--out` path instead of deleting prior results.

For any observed positive/negative imbalance or data leakage concerns, inspect `dev_split_seed*.csv`, `manifest.json`, and the audit files before interpreting results.
