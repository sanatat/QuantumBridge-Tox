# QuantumBridge-Tox v0.4 — CPU-only development experiments

This **adds one new script** to the user's existing QuantumBridge-Tox project. It does not replace or edit `gnn_quantumbridge.py` (v0.3), original CSV datasets, original `tox_split.csv`, trained `.pt` checkpoints or previous results.

## Main research question

Can pretraining a small molecular message-passing GNN to predict **quantum-chemical DFT properties from molecular graphs** improve Tox21 NR-AhR activity prediction, beyond learning from scratch and beyond **nonquantum** pretraining on RDKit-computable descriptors?

## Required existing project files

- `gnn_quantumbridge.py` (the original v0.3 supplied by the user; must be in the **same directory** as the new script)
- `data/qm9.csv`
- `data/tox21_clean.csv.gz`
- `results/gnn_v03_5k/tox_split.csv` (frozen test split from original experiment)
- existing CPU-only `torch`, `numpy`, `pandas`, `rdkit`, `scikit-learn` installation

Do **not** rerun v0.3 or overwrite its results. The v0.4 script refuses nonempty output folders.

## Install

Download `QuantumBridge-Tox-v0.4.zip` to `~/Downloads`. Then:

```bash
cd ~/Downloads
unzip -n QuantumBridge-Tox-v0.4.zip -d QuantumBridge-Tox
cd QuantumBridge-Tox
source .venv/bin/activate
python gnn_quantumbridge_v04.py --help
```

The archive contains only `gnn_quantumbridge_v04.py` and this README. It does **not** contain the datasets, v0.3 script or a Python environment.

## First: quick CPU smoke run

```bash
cd ~/Downloads/QuantumBridge-Tox
source .venv/bin/activate
mkdir -p logs
set -o pipefail
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v04.py \
  --mode multiseed --seeds 42 \
  --n-qm9 1000 --qm9-val-n 100 \
  --pretrain-epochs 2 --finetune-epochs 2 --patience 2 \
  --hidden 32 --batch 32 --threads 2 \
  --out results/gnn_v04_smoke_1k \
  2>&1 | tee logs/gnn_v04_smoke_1k.log
```

Expected variants: `random_forest`, `scratch`, `full`, `rdkit`. They are evaluated on a **new, development-only outer fold**. The old v0.3 test molecules are **never evaluated**.

**`--n-qm9` is the number of QM9 PRETRAINING examples; `--qm9-val-n` is additional, disjoint QM9 validation examples.**

## Follow-up A: multi-seed (3 grouped development splits)

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v04.py \
  --mode multiseed --seeds 42,123,2026 \
  --n-qm9 5000 --qm9-val-n 500 \
  --pretrain-epochs 8 --finetune-epochs 12 --patience 4 \
  --hidden 32 --batch 32 --threads 2 \
  --out results/gnn_v04_multiseed_5k \
  2>&1 | tee logs/gnn_v04_multiseed_5k.log
```

Three model conditions are trained for each split: scratch, full DFT pretraining, and RDKit-descriptor pretraining; Random Forest provides a non-GNN comparator. Each seed changes both the grouped development split and model randomness; repeated splits are correlated and do not yield independent test evidence. Training may take considerable time on a CPU.

## Follow-up B: DFT target-family ablation

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v04.py \
  --mode ablation --seeds 42 \
  --n-qm9 5000 --qm9-val-n 500 \
  --pretrain-epochs 8 --finetune-epochs 12 \
  --threads 2 \
  --out results/gnn_v04_ablation_5k \
  2>&1 | tee logs/gnn_v04_ablation_5k.log
```

Variants:

- `scratch`: no pretraining
- `full`: QM9 DFT `mu`, `alpha`, `homo`, `lumo`
- `orbital`: DFT `homo`, `lumo` only
- `response`: DFT `mu`, `alpha` only
- `rdkit`: **non-DFT control** using molecular weight, TPSA, LogP, H-bond donor count on the **same QM9 molecules**

Note that `--mode ablation` always evaluates these five GNN conditions plus Random Forest. To estimate variability use `--seeds 42,123,2026`, but this takes longer.

## Follow-up C: learning curve

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -u gnn_quantumbridge_v04.py \
  --mode curve --seeds 42 \
  --curve-sizes 1000,5000,10000 \
  --qm9-val-n 500 \
  --pretrain-epochs 8 --finetune-epochs 12 \
  --threads 2 \
  --out results/gnn_v04_curve \
  2>&1 | tee logs/gnn_v04_curve.log
```

The QM9 training subsets within a **single curve run** are nested and share a fixed disjoint QM9 validation set. Curve sizes specify the number of **training** molecules, not the total QM9 sample including validation.

## Output files

Each fresh `--out` directory contains:

- `development_results.csv`: one row for each seed/variant, with PR-AUC, ROC-AUC and separate inner-validation selection diagnostics.
- `summary.csv`: mean and sample standard deviation across development seeds (SD is blank/NaN for one seed).
- `paired_deltas.csv`: paired performance difference of each variant versus scratch on the **same outer development fold**.
- `dev_split_seed<seed>.csv`: exact InChIKeys, scaffold and membership of inner train / early-stopping validation / outer-development evaluation.
- `manifest.json`: complete run settings, frozen old split hash and critical methodological cautions.
- Optionally `checkpoints/*.pt` when `--save-checkpoints` is supplied (not enabled by default).

Inspect:

```bash
python - <<'PY'
import pandas as pd
p = 'results/gnn_v04_multiseed_5k'
print(pd.read_csv(p + '/summary.csv').round(4).to_string(index=False))
print(pd.read_csv(p + '/paired_deltas.csv')[['seed','variant','delta_roc_vs_scratch','delta_pr_vs_scratch']].round(4).to_string(index=False))
PY
```

## Integrity / scientific caution

1. The existing frozen v0.3 **test** set (1,219 Tox21 NR-AhR chemicals) is removed from the development pool by exact InChIKey. It is not used for model selection or evaluation in v0.4. The script checks the frozen split against all currently cleaned Tox21 identities, and rejects discrepancies.
2. Outer development evaluation is scaffold-grouped and distinct from the **inner** validation fold used for early stopping. Development splits are repeated, correlated; they are **not an independent, unseen external test**.
3. QM9 preprocessing from v0.3 removes all repeated QM9 InChIKeys and removes **all** InChIKeys in the complete standardized Tox21 file, not only NR-AhR labels.
4. Models use 2D atom/bond connectivity; no 3D coordinates are passed to the GNN. Quantum labels are supervised regression targets; they are *not* quantum features concatenated to Tox21 at inference time.
5. This is still an exploratory pilot. The frozen v0.3 test was already examined in earlier work. Claims of generalization or DFT improvement ultimately require a genuinely independent external benchmark, rigorous paired comparisons, and careful coverage/domain-shift analysis.
6. DFT target normalization uses only the **QM9 pretraining** data. No Tox21 toxicity labels are used during QM9 pretraining.
7. Synthetic smoke tests confirmed code paths, **not** scientific performance. The real dataset experiments must be executed on the user's own device.
